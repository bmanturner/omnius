# Documentation capability coverage matrix

This matrix assigns every canonical registry entry to one owner page and keeps maturity, implementation, profile selection, and public exposure independent. Profile selection, specifications, catalogs, generated artifacts, and library source do not by themselves prove runtime exposure. All verification results intentionally begin as `not run` until the named method is exercised and its result is retained.

Profile-level claims are governed by the 23-row [availability and exposure map](reference/availability-and-exposure-matrix.md) and `target/profile-matrix/report.json` schema 5. Runtime profiles exclude every tooling module. Only the untouched generated root can reach `assembled`, and only after all required composition/process/protocol checks pass. Required skips, unresolved application contributions, `llm-embeddings`, synthetic fixtures, missing dependency-outage evidence, contract/runtime mismatch, enterprise MCP/Apps gaps, and full-reference product ports keep the row unassembled regardless of library test coverage.
